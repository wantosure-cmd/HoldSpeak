## 每项的验收记录

记录 OS、目标应用版本、语音软件版本、快捷键、协议、输入位置和日期。

1. 单击定位、双击选词、拖动选字均正常。
2. 输入框静止长按开始真实录音，非输入框不开始。
3. 松开结束并正确回填。
4. 按住期间移动不继续拖选。
5. 切到其他应用、达到最长保持或暂停后释放。
6. 主进程异常退出，恢复进程尝试释放；验证真实键状态。
7. 多屏、混合 DPI、左手鼠标、权限变化。

macOS 单独验证实体鼠标和触控板实际按压、Event Tap 被禁用恢复、修饰键 flagsChanged、签名包的授权身份。轻点与力度点按尚未定义为支持。

用户当前没有 Mac。交叉构建不能替代实机；未来需要贡献者或可用 Mac 完成验收。

2026-10-08 浏览器识别测试：Chrome 155.0.8059.40、Edge 154.0.4258.62 各 8 项通过。使用独立 profile 和本地固定 HTML，未使用 `--force-renderer-accessibility`，未发送语音快捷键。测试只证明列出的控件识别和拒绝行为，不能证明输入法启动、结束及回填，不能外推到任意网页或其他应用。

0.1.4 补充动态地址栏回归：旧版在写入短文本后，建议背景浮层使鼠标命中返回 Pane，复核报 not_confirmed_editable。已观察 Chrome 的 TopBackgroundView 和 Edge 的 View 均位于 RoundedOmniboxResultsFrame 下，焦点仍在原 OmniboxViewViews。新适配对齐地址栏边界并保持原控件 ID，三次文本更新及状态机持续保持、建议区域拒绝测试通过。快捷键会话使用测试替身，没有真实录音；用户仍需复测微信输入法。

0.1.5 的定向元数据检查：ChatGPT.exe 宿主一处 Edit 的 Value/Text 只读属性均为 false；Weixin.exe 两处 Edit 均为可写；当前 Feishu.exe 仅观察到只读 Document。检查未读取名称、正文或标题，不能确定每个候选对应主输入框、搜索或其他位置。后者也不能据此认定飞书所有输入框均不支持。

## 发布门槛

2026-10-08 用户反馈：Chrome 和 Codex 当前输入框已经可以语音输入。该反馈补充真实使用证据；未提供具体版本、主／跟进输入位置或全部异常场景，不外推为所有控件及 Mac 已通过。本轮默认启用和悬停优化需要继续在新包上复测。

- 必须在 Windows 和真实 Mac 上完成最少一种 hold 输入法的完整录音和回填。
- 必须覆盖用户提出的 Codex、浏览器地址栏、网页、微信和飞书，逐项记录支持或明确限制。
- 发布前完成活动期间焦点保护与异常循环处理的运行验证、队列压力测试、软件包签名策略和可操作的诊断流程。
